# Research: How does Osiris build its layers and panels? (ticket #3)

Paths are relative to `src/` at commit 0aaba38. Read-only research; no code was run.

## Findings (file:line)
### Structure: one giant map component + one giant page, no layer registry
- Map is ONE component components/OsirisMap.tsx (3424 lines). Page app/page.tsx (2354 lines) owns state; LayerPanel.tsx (555) is the toggle UI.
- maplibre-gl pinned 6.7.0 (package.json); no three.js dep anywhere (grep). Worker vendored: OsirisMap.tsx ~L335 setWorkerUrl(/vendor/maplibre/<ver>/...), tools/prepare-map-worker.mjs run in predev/prebuild. Basemap = CARTO dark-matter style URL (OsirisMap.tsx:337), tiles proxied via /api/proxy-tiles (transformRequest ~L364). Map options: zoom 1.8, minZoom 1.5, maxZoom 18, maxPitch 85 (~L343-363).
### Adding sources/layers (the plug-in point)
- All inside one map.on('load') handler (OsirisMap.tsx:400-~927): L438 `sources=[...]` list then `sources.forEach(s=>map.addSource(s,{type:'geojson',data:EMPTY_FC}))`; then ~60 hand-written map.addLayer calls (circle glow/dots + symbol label triplets, e.g. eq L484-489, cctv L500-511, maritime L701-712, sdk lines L871-909). Ends with setMapReady(true) at L~927 and map.once('idle') -> onReady (splash).
- A new group = add source id to the L438 list, add addLayer calls before setMapReady, add id(s) to CLICKABLE_LAYERS (set ~L1148) plus a map.on('click', layerId, ...) popup handler (pattern: eq-circles L1131; popups built as HTML strings with htmlEsc/idSafe/urlSafe helpers).
- Self-contained alternative (cleaner for us): module that attaches layers itself, e.g. lib/oi/globe.ts attachOi(map) (L644; adds custom layer + helper layers L662-713), wired by useEffect at OsirisMap.tsx:~2727 with cleanup globe.destroy(); also lib/live-clouds-layer.ts, lib/satellite-layer.ts. Use this shape for situational-map layers.
- Data push: effects keyed [mapReady, data.x, activeLayers.x] call setGeo(sourceId, features) (helper L~1840: getSource().setData({FeatureCollection})) — e.g. flights effect ~L1855, earthquakes ~L1925. Off toggle => push [] (flights) .
- Visibility: single effect OsirisMap.tsx:2403-2443 `setVis([layerIds], activeLayers.key)` -> setLayoutProperty(visibility) (setVis helper L1848-1851). New layers need a line here.
- Layer ordering: new layers inserted before 'day-night-fill' (satellite imagery L2674, clouds L2705); terrain mode reorders draped types (fill/line/raster/hillshade/background) below overlays via lib/terrain-layer-order.ts batchTerrainLayers (L1-73) — new fill/line layers get moved under markers when terrain is on.
- Per-theme colours: palette read from CSS vars `--map-*` (lib/map-palette.ts, readMapPalette), recolour effects use setPaintProperty (e.g. cctv ~L1972). Map is remounted on theme change (`key={osirisTheme}` page.tsx:1540).
### Toggles and panels
- Toggle state: page.tsx:460-505 `activeLayers` useState object of booleans (defaults: most off). Add a key there.
- Toggle UI: components/LayerPanel.tsx LAYER_GROUPS array (L~50-170): {label, fullLabel, icon, layers:[{key,label,dataKey,description?,catKey?,requires?,parent?}]}. `dataKey` = data bucket(s) for the count badge; `requires` hides until server capability flag (capabilities state page.tsx:631, probe e.g. /api/cloudflare-radar?probe=1 page.tsx:686); `parent` = indented sub-layer. toggle() L221 flips activeLayers[key]; toggleGroup L236. Same LayerPanel rendered desktop (page.tsx:1781) and mobile (page.tsx:2183).
- Other panels (Intel feed, Markets, OSINT, OI, LiveAlerts...) are components mounted in page.tsx with show* booleans + keyboard shortcuts (page.tsx ~L798-812); mobile uses bottom tabs (page.tsx ~L2123-2210).
### Data fetching
- Server: one Next route per feed, src/app/api/<name>/route.ts, e.g. api/earthquakes/route.ts (fetch upstream w/ AbortSignal.timeout(10000), normalise to {lat,lng,...}). ~60 routes; CCTV has per-region modules under api/cctv/.
- Client: page.tsx:944-965 fetchEndpoint(url, transform?, opts, {skipWhenHidden}) merges into dataRef.current, bumps setDataVersion (data is a mutable ref object, page.tsx:175-177; panels/map re-render on dataVersion). Core feeds polled at mount (page.tsx ~L975-1010); layer-gated fetch in effect keyed on activeLayers (L~1033-1142) using layerFetchedRef Set (fetch once on first toggle) or loadLayerOnce(key,url,transform) (L1118, releases mark on failure); polling intervals L1146-1186; SSE for malware (L1195 EventSource /api/malware/stream); cameras via lib/camera-catalog loadCameraCatalog (L1021).
### Globe projection vs zoom
- lib/map-projection.ts: GLOBE_PROJECTION={type:'globe'} (L8); TERRAIN_GLOBE_PROJECTION = interpolate zoom 7 'vertical-perspective' -> 9 'mercator' (L18-20) used only when terrain on; applyMapProjection(map, mode, terrainEnabled) L22-32 (setProjection only if type differs). Applied in OsirisMap.tsx effect ~L2533-2562 (also sets sky + pitch 20 on globe, pitch 0 on mercator).
- page.tsx:431 mapProjection state 'globe'|'mercator'; toggled by ViewSegment 3D/2D (L1701-1702), key 'g', selectFlatMap (L~616) which also turns off terrain_3d/terrain_elevation. on3DModeSelected (L627) forces globe. Terrain only when projection==='globe' (L1544).
- Terrain: lib/map-terrain.ts attachTerrain — raster-dem 'osiris-dem://' protocol, activates at zoom>=10 after 500ms settle, releases <9.5 (L8-12), maxPitch capped 60, pixelRatio capped 1.5.
- MapLibre side (primary): developer-guides/globe.md @v6.7.0: "globe projection automatically switches to mercator projection around zoom level 12" (precision), smooth shader-level transition; planet size auto-compensates with latitude. Style-spec: projection supports interpolate on zoom (vertical-perspective -> mercator).
### Does maplibre-gl 6.7 globe support fill-extrusion and custom (three.js) layers? YES to both (primary sources, tag v6.7.0 of maplibre/maplibre-gl-js)
- fill-extrusion on globe: official example test/examples/display-a-globe-with-a-fill-extrusion-layer.html (setProjection({type:'globe'}), extrude polygons heights 150-600 km). CHANGELOG 6.12.0 (AFTER 6.7): "Fix queryRenderedFeatures missing fill-extrusions on globe once it renders as mercator" => on 6.7 queryRenderedFeatures on extrusions after globe->mercator transition is buggy; fix by upgrading to >=6.12 or avoid relying on queryRenderedFeatures for buildings. Osiris 3D buildings (OsirisMap.tsx:2605-2640, 'osiris-3d-buildings', source 'carto', source-layer 'building', minzoom 14.5, toggle terrain_3d) are always past the zoom-12 mercator switch so they run in mercator anyway.
- Custom layers: CustomLayerInterface (src/style/style_layer/custom_style_layer.ts): renderingMode '2d'|'3d' ('3d' needed for shared depth buffer / globe occlusion), render(gl,args) with args.shaderData {variantName, vertexShaderPrelude, define (#ifdef GLOBE)} and args.defaultProjectionData {mainMatrix, projectionTransition, tileMercatorCoords, clippingPlane, fallbackMatrix}; under globe, elevation in projectTileFor3D is metres above the sphere. 6.0.0 exposed getProjectionData; 6.4.1 "Give custom layers the live globe transition in defaultProjectionData.projectionTransition" (so >=6.4.1 ok on 6.7). 6.13.0 adds experimental renderToTerrainTile/terrainTileRevision (NOT in 6.7: custom layers cannot drape on terrain in 6.7).
- three.js on globe: official example test/examples/add-a-3d-model-to-globe-using-threejs.html (three 0.169): THREE.WebGLRenderer({canvas: map.getCanvas(), context: gl}), autoClear=false, renderingMode '3d', per-frame renderer.resetState(), isGlobe = projectionTransition>0, build globe model matrix (rotY(lng), rotX(-lat), translate z 1+alt/R, scale 1/6371008.8) vs mercator matrix (MercatorCoordinate.fromLngLat + meterInMercatorCoordinateUnits), camera.projectionMatrix = mainMatrix * model; map.triggerRepaint(); canvasContextAttributes:{antialias:true} for MSAA. Caveat: must switch matrix when transition passes (high zoom = mercator).
- Osiris precedent for raw-WebGL2 custom layers (no three): lib/satellite-layer.ts (type 'custom' L384, renderingMode '3d' L387; uses shaderData prelude + projectTileFor3D (header L1-24); sets all u_projection_* uniforms from defaultProjectionData L369-379 or nothing draws; per-projection program cache lib/satellite-programs.ts; GPU pick pass because queryRenderedFeatures cannot see custom layers L137; SAT_MAX_ZOOM=7 L62 stops drawing past it); lib/live-clouds-layer.ts (custom, '3d' L449-450, tiles via map.coveringTiles, CLOUDS_MAX_ZOOM); lib/oi/globe.ts (custom '3d' L449). Canvas context fallback ladder OsirisMap.tsx:~371-380 (maplibre 6 is WebGL2-only).
- Gotchas for 3D handoff: hit-testing custom layers = own GPU pick (click handler OsirisMap.tsx ~L1160 defers to CLICKABLE_LAYERS then oiGlobe.hit then sat pick); attribution for custom layers needs a dummy geojson source (OsirisMap.tsx:2711); terrain on => globe->mercator by zoom 9, and custom layers do not drape on terrain in 6.7; when 2D (mercator) pitch forced 0.
## Suggested "shape" takeaways
1. New layer group = (a) key in page.tsx activeLayers, (b) LayerPanel LAYER_GROUPS entry, (c) /api route + layer-gated loadLayerOnce, (d) attach module like attachOi called from one useEffect in OsirisMap, (e) setVis line, (f) CLICKABLE_LAYERS + click popup. Keep new code out of the 3.4k-line load handler.
2. High-zoom 3D (buildings/three.js): both work on 6.7 but run in mercator past ~z12 (and by z9 with terrain); build matrix per projectionTransition; use renderingMode '3d'; consider bumping maplibre >=6.12 for fill-extrusion queryRenderedFeatures fix.
Gist for map Decisions-so-far: "Osiris has no layer registry: layers = hand-wired addSource/addLayer in OsirisMap's load handler + activeLayers key + LayerPanel entry + /api route; plug in via an attachX(map) module (like lib/oi/globe.ts); maplibre 6.7 globe supports fill-extrusion and custom/three.js layers (mercator past ~z12), so 3D at high zoom is feasible (no three dep yet)."
