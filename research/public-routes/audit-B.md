# Audit lane B: situational-globe public-demo API routes

Base: /Users/robinsverd/Thrivbe-AI/lab/situational-globe/src. Paths below are relative to that. Read-only review; nothing was run. "Workers" notes are from reading imports, not from a deploy test, so mark them "unverified until a build runs".

Shared facts:
- lib/ssrf-guard.ts: safeFetch blocks private ranges and re-validates each redirect hop for private IPs only. It never re-checks any host allowlist. DNS is checked with `node:dns` `lookup` (line 161), then fetch re-resolves (TOCTOU/rebinding, comment at 11-15 admits it). The rate limiter (219-233) is an in-memory Map per isolate, so on Workers it does not bind across isolates.
- lib/httpJson.ts:1-3,42 uses `node:https` + `zlib`. lib/nominatim.ts:1 uses `node:fs`. lib/cctv-snapshot.ts:1-3 uses fs/zlib/crypto and writes `.cache`. None of these is Workers-safe without proof.
- No route here has auth, CORS control (two set ACAO `*`), or a global rate limit. Only arcgis (mode 2) and cctv/frame call isRateLimited.

## Must-fix for the spec

1. cctv/proxy: switch OFF, or rebuild it: exact-host allowlist (no `s3-eu-west-1.amazonaws.com` wildcard), `redirect:'manual'` with no follow, image-only via magic bytes, `nosniff`, TLS verification on, size cap, plain `fetch`. Today it is an open redirect-following fetcher that returns attacker-chosen content types from our origin (proxy/route.ts:17,43,135-138,188).
2. arcgis `?service=`: restrict to `*.arcgis.com`, port 443, no redirects, byte cap. Otherwise OFF (arcgis/route.ts:253-301; ssrf-guard.ts:205-210).
3. safeFetch (lib/ssrf-guard.ts:184-215): follow no redirects, or re-apply the caller's host allowlist on each hop; add a response size cap. This fixes resolve, stream-status, arcgis and the frame fetch in one place.
4. cctv (root): public requests must only read a prebuilt static catalogue; no upstream fan-out, no fs, no background timers (route.ts:947-958,1016; cctv-snapshot.ts:64).
5. Switch OFF in the public build: cctv/frame, cctv/proxy (unless fixed as in 1), cctv/resolve, cctv/stream-status.
6. geo: replace the 3 third-party IP lookups with Cloudflare `request.cf`; stop honouring client-written X-Forwarded-For (geo/route.ts:25-80; ssrf-guard.ts:298).
7. Edge rate limiting: the in-memory limiter (ssrf-guard.ts:219) is per isolate and does not bind on Workers. Put a Cloudflare rate-limit rule (or the Workers rate-limiting binding) on every `/api/*` route. None of my routes except arcgis mode 2 and cctv/frame call it today.
8. Input clamps: sentinel (radius, days), directions (`via` count), geosearch (`q` length), flight-route (callsign/icao24 charset and length), region-dossier (lat/lng bounds).
9. Public OSM demo servers (Valhalla, OSRM, Photon, Nominatim) will see our Cloudflare egress and ban it; self-host, or switch these features off in the demo (directions, geosearch, geo/reverse, region-dossier).
10. Workers compatibility to verify with a build: `node:https` in lib/httpJson.ts (directions, geosearch, region-dossier), `node:fs` in lib/nominatim.ts and lib/cctv-snapshot.ts, `node:dns` in lib/ssrf-guard.ts:1, `node:http/https/dns` in cctv/proxy, `runtime = 'nodejs'` in cctv/texas/snapshot. Unverified: whether nodejs_compat covers each.
11. No secrets or env values were found in these routes' responses; the only env use is `process.env.NODE_ENV` (geo/route.ts:18) and `OSIRIS_CCTV_SNAPSHOT` (cctv-snapshot.ts:32). Error messages echo `err.message` in arcgis (334), cctv/proxy (195) and geo (95); trim them.
12. Not read, so unknown: lib/stealthFetch.ts internals, lib/airports.ts `lookupAirportAsync` (may fetch), and the per-region cctv fetchers under cctv/*.ts (all hit fixed feed URLs but were not individually checked).
