# Audit lane C: /api/osint/* (18 routes)

Base: `/Users/robinsverd/Thrivbe-AI/lab/situational-globe/src`. Routes are `app/api/osint/<name>/route.ts`. Shared code: `lib/ssrf-guard.ts` (SG), `lib/sherlock.ts`, `lib/sanctions.ts`, `lib/chainIntel.ts`.

## Cross-cutting findings (apply to many rows)

- **C1. The rate limiter does not hold on Workers.** `SG:219-233` is an in-memory `Map` per isolate. Cloudflare runs many isolates and recycles them, so the 20/min and 3/min limits are not enforced in practice. Each call also loops over the whole map (`SG:223`). The IP identity is fine: `getClientIp` prefers `cf-connecting-ip` (`SG:255`).
- **C2. Six routes have no rate limit at all:** github, hudsonrock, leaks, mac, phone, shodan.
- **C3. `sweep` has its own limiter that trusts a client-written header.** It reads the leftmost `x-forwarded-for` (`sweep/route.ts:67-68`), which a caller can set to anything.
- **C4. The OFAC list loads inside the request path.** `lib/sanctions.ts:19-22,116-187` downloads about 7 MB of CSV, parses it character by character and builds indices. This runs on every cold isolate, with unbounded CPU and memory. It is triggered by `sanctions`, `ip` (`ip/route.ts:72`), `whois` (`whois/route.ts:103`) and `crypto` (via `lib/chainIntel.ts`). `search()` also runs `normName` (a regex) over every entry and alias per request (`sanctions.ts:229-236`). That is a cheap way for a stranger to burn CPU.
- **C5. `ssrf-guard.ts` imports `node:dns/promises` and `node:net` (`SG:1-2`).** Every route that imports the file needs `nodejs_compat` and a Workers-supported `dns.lookup`. Only `whois` calls `lookup` (through `safeFetch`, `SG:161`). Verify this on a preview deploy. The DNS check is also a time-of-check/time-of-use gap (admitted at `SG:11-14`), but Workers cannot reach RFC1918 anyway, so SSRF to internal hosts is low impact.
- **C6. Secrets and env.** No route reads a paid key into a request. `ETHERSCAN_API_KEY` and `HELIUS_API_KEY` appear only as booleans (`chainIntel.ts:544-545`), exposed by `crypto?probe=1` (`crypto/route.ts:22-23`). That is a minor disclosure. Nothing in these routes (or `lib/sherlock.ts`, `lib/sanctions.ts`) returns env values.
- **C7. Several routes return raw `error.message` to the caller** (`github:37`, `leaks:49`, `mac:36`, `shodan:36`, `sanctions:61`). This is low severity and only echoes upstream status text.
- **C8. `ip-api.com` is called over plain HTTP** (`ip:30`, `bgp:25`, `sweep:79`). The free tier allows 45 requests per minute per egress IP and is non-commercial only, and Workers egress IPs are shared. Expect 429s and a ToS problem for a partner-facing demo.
- **C9. No route uses raw sockets, port-43 whois, `fs` or `child_process`.** `whois` uses RDAP over HTTPS. No Workers-incompatibility found beyond C5 and the points under `phone`, `username` and `fingerprint` below.

## Must-fix for the spec

- **Switch off in the public build (OFF):** `crypto`, `fingerprint`, `github`, `hudsonrock`, `leaks`, `phone`, `sanctions`, `sweep`, `username`. These are person-lookup, breach-lookup and enumeration tools, or heavy and duplicate. Delete the routes and drop `lib/sherlock.ts`, `lib/sanctions.ts`, `lib/chainIntel.ts` and `google-libphonenumber` from the Worker bundle. Prefer removal at build time over a runtime flag so a stranger cannot toggle them.
- **Keep with changes (FIX), only if the UI needs them:** `bgp`, `certs`, `dns`, `ip`, `mac`, `shodan`, `threats`, `whois`.
  - Remove the OFAC cross-check from `ip` (`ip:64-78`) and `whois` (`whois:94-109`).
  - Remove the HEAD probe from `whois` (`whois:60-92`).
  - Validate `shodan` input as a public IP (`shodan:12`).
  - Cache `threats` (Tor list and OTX pulses) and `certs`/`dns`/`bgp`/`ip` per query (Cache API or KV).
- **KEEP:** `cve` only.
- **Rate limiting:** replace the in-memory limiter with an edge control. Use a Cloudflare WAF rate-limiting rule on `/api/osint/*`, or a Workers Rate Limiting binding keyed on `cf-connecting-ip`. Do not rely on `lib/ssrf-guard.ts:221` (C1). Also fix `sweep:67-68` if the route is kept.
- **Gate `/api/osint/*` with an explicit allowlist.** There is no middleware, so a route you forget to delete stays public. A build-time route allowlist (or a tiny `src/middleware.ts` that returns 404 for anything not allowlisted) is the safer default.
- **Do not set `ETHERSCAN_API_KEY`, `HELIUS_API_KEY` or any other paid key on the public Worker** (C6). Remove the `?probe=1` key disclosure if `crypto` is kept (`crypto:22-23`).
- **Check on a preview deploy:** `nodejs_compat` plus `node:dns/promises` and `node:net` (C5), and the script-size limit after removals. Drop `node:dns` entirely if `whois` loses `safeFetch`.
- **ip-api.com:** switch to an https source or `request.cf` (C8). The free tier is non-commercial and rate-limited per egress IP.
- **Stop echoing `error.message` to callers** (C7) in any route that is kept.
